Goal timeline-gantt-display — outcome: shipped to PR (branch feat/timeline-gantt-display, 2026-11-26).

What changed: TripTimeline (src/features/trip/TripTimeline.tsx/.css) was rebuilt as a compact Gantt-style band: header row (one-line detail readout + prev/next arrows passed in through an `actions` prop), a horizontally scrollable track where each stay is a labelled button bar positioned by date, and a separate aria-hidden date axis below. The active stop's bar has aria-current and is scrolled into view inside the strip (scrollTo on the strip only, never scrollIntoView; `auto` behaviour under reduced motion). The carousel scroll-sync effect, gap elements, floating duration badges and floating tooltip were removed. First component tests added (TripTimeline.test.tsx, 22 tests).

Key decisions:
- Floating tooltip replaced by a header readout: `.timeline-scroll` needs overflow-y hidden, which clips floating tooltips; reserving space for them was the cause of the old dead vertical space.
- Arrows are owned by TripForm and passed as `actions`; with fewer than 2 dated stops the timeline renders only the actions.
- Day width is a component-local CSS variable `--timeline-day-width` (96px, 72px under 600px); colours use existing tokens only.
- First/last axis markers are edge-aligned by :first-child/:last-child rules so labels are not clipped.

Remember next time: a blanket "no vertical value above N px" criterion must list every structural exemption (bar, track, axis) or it becomes a criteria defect. Open follow-up: the auto-scroll effect depends only on currentStopId and does not re-run if timeline data arrives later.
