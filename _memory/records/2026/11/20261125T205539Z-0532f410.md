Pitfall: a build-output acceptance criterion placed in a task that adds no consumer.

What went wrong: task 01 (version contract) had a criterion that the built bundle under dist/assets contains the commit id from dist/version.json. The task only defined the Vite `define` globals and src/config/version.ts; nothing imported that module until a later task, so Vite tree-shook the value out and the grep printed 0. The evaluator classified it criteria-defect and the goal stalled for a user-approved criterion correction.

How it was detected: the implementer reported the criterion unmet and the evaluator proved in a scratch copy that one import makes the grep pass.

How to avoid it: put "the bundle contains X" checks in the task that adds the first importer of X, not in the task that defines X. More generally, a criterion that inspects build output must be satisfiable by files inside that task's write fence.
