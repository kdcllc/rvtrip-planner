Pitfall: in this dev environment `rg` is a bash shell function (it wraps the Claude Code binary), not a binary on PATH.

What went wrong: Python `subprocess.run(cmd, shell=True)`, and any non-interactive child shell, cannot see it and returns zero hits silently. In goal custom-email-domain a terminal agent re-running goal.md searches this way reported "DIFF want-only=<all>, got-only=[]" and misread it as real.

How it was detected: every search lost every hit at once, which is implausible.

How to avoid it:
- Run `export -f rg` before scripts that spawn bash to run rg, or use `bash -c` with the function exported.
- Treat an empty got-set across all searches as a tooling failure, not a result.

Related: an evaluator ran `git stash` / `stash pop` mid-evaluation. Context packages should explicitly forbid state-changing git commands (stash, checkout, reset, restore, add).
