Goal stop-form-restructure (branch feat/stop-form-restructure, 2026-11-25). Outcome: implemented, audited APPROVED, Quality Checks green; visual QA deferred to a manual browser pass by the user.

What shipped: the Add/Edit Stop drawer (src/features/trip/StopFormFields.tsx, StopDrawer.tsx/.css, TripForm.tsx) now shows four essentials (address, title, arrival, departure) plus a Starting point checkbox, with native details/summary sections Stay, Notes and (edit only) Travel & costs. Only the address is required; the title is derived from the address (src/domain/trip/stopFields.ts deriveStopLabel) and dates are optional. Duplicated fields were merged in the data model too: source.fees, source.amenities and reservationNote were removed from TripStop (client and api/src/shared/types.ts); foldLegacyStopFields folds their text into note (or nightlyCost when fees was only a price). STOP_NOTE_MAX_LENGTH is 2000.

Key decisions: fold on every load path instead of a server migration (the API stores stops as sent); deprecate-then-delete the type members across tasks so parallel tasks stay type-clean; reservation details render only when status is reserved; campground and reservation fields live in one Stay section.

Remember next time: the fold must run on every path a server or file payload enters state — loadTrips, readLegacyLocalTrips, file import AND the 409 conflict `current` returned by saveTrip (the final audit caught the last one). The follow-ups.md backlog lists open items: no delete confirmation, no unsaved-changes warning, no focus trap, map popup HTML is not escaped, legacy site types outside the select list, folded notes can exceed 2000 characters.
