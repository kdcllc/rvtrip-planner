Pitfall: `_kit/memory.sh prune --apply`, run at the start of a new /feature goal, deletes the work folders of finished goals under `_memory/work/goals/`, including their `checks/` scripts.

What went wrong: in goal branded-email, task 02 AC4 reused `_memory/work/goals/custom-email-domain/checks/arm_check.py` as a regression check. That file had been pruned minutes earlier, so the criterion pointed at a missing file. It was caught at pre-flight when the command failed with "No such file".

How to avoid it:
- Never reference another goal's work folder from criteria; copy the checker into the current goal's `checks/`, or rely on `git diff` / build checks.
- Checkers worth keeping long-term belong in a tracked location, not `_memory/work/`, which is gitignored.
