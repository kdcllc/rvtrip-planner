Pitfall: planning a dead-code sweep and a UI removal from a narrow grep.

Two planning gaps surfaced in goal app-versioning-and-cleanup. First, the task that removed the "Open in Google Maps" buttons from src/features/trip/TripForm.tsx initially told the worker to remove "selection UI used only by them"; the Select all / Deselect all / N selected controls and per-stop checkboxes sit in the same block but also drive export and print in src/app/AuthenticatedApp.tsx. The goal evaluator caught it before execution. Second, a sweep task with a whole-tree fence removes exports that the plan's Consumers table never listed (the final audit flagged getConfig, serializeCookie, revokeInviteCode and others), so the trace needs an amendment after the sweep.

How to avoid it: before writing a removal requirement, grep the props and handlers of the surrounding block for other consumers and name what must stay. For a sweep task, plan an explicit post-sweep step that records a HEAD-based search (git grep ... HEAD) of every removed symbol and adds the Consumers rows, instead of waiting for the audit to ask. Also note `npx knip` is blocked by the permission classifier in this environment; a scripted export/grep inventory worked.
