Pitfall: a merged PR with a new SQL migration deploys code before the schema exists when migrations are manual. In trips-db-landing-invites, migration 002 (dbo.user_trips) was never applied, and a stale local master meant a manual run applied only 001 — production sign-in then failed with "Internal server error" (Msg 208 Invalid object name). Avoid: migrations now run in azure-dev.yml before azd deploy; when running scripts/db-migrate.sh by hand, `git pull` first and verify the migration file list.
