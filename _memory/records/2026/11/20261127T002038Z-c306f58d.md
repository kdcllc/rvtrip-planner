Pitfall: whole-day differences computed from two local-midnight Dates with Math.floor or Math.ceil are wrong across daylight-saving changes. Spring-forward makes the span 1 hour short, so floor loses a day; fall-back makes it 1 hour long, so ceil gains a day.

Seen in goal timeline-gantt-display (2026-11-26): src/utils/date.ts getStopDatePosition floored the difference, so on a trip starting before the March change every later stop was drawn one day early on the timeline, out of line with the date axis. Combined with a "+2% offset for stops sharing a start date" hack it made bars overlap. Reported by the user from a 26-stop trip after the PR was opened; unit tests had not caught it because fixtures did not cross a DST boundary and CI's timezone has none.

How to avoid: use Math.round for day differences between local midnights (or compute in UTC). Test date maths with a fixture that crosses a DST boundary and set process.env.TZ = 'America/New_York' in the test, with a guard that fails if the runtime ignored it. For timeline layout, never nudge positions to avoid overlap; assign lanes (greedy interval packing on integer day spans) instead.
