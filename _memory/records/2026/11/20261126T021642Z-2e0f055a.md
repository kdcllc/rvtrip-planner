Pitfall: "no leftover references" grep criteria with a fixed allow-list go stale as soon as later tasks add tests.

In goal stop-form-restructure, task 05 removed three stop fields and its acceptance criterion grepped for the field names with an allow-list of legacy readers. Two legitimate test files then tripped it: a calendar test (task 03) that deliberately feeds legacy data to prove it is not emitted, and the form test (task 06) that asserts the keys are absent. The first needed a user-approved criterion correction mid-goal; the second was only noticed by the final audit.

How to avoid it: when writing a removal-trace criterion, scope the grep to non-test product files (exclude *.test.ts and *.test.tsx and fixtures), or state up front that tests asserting absence or feeding legacy input are allowed. Decide this at planning time so the criterion does not need a correction after other tasks land.
