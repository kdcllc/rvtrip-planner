Goal multi-vehicle-garage (2026-11-27): an account now keeps a garage of up to 10 vehicles (name, fuel type, MPG, tank) with a default, and each trip picks its vehicle (`Trip.vehicleId`, falls back to the default). Fuel cost and the "Fuel price basis" use the trip's vehicle.

Shape: `GET/PUT /api/vehicles` (api/src/functions/vehicles.ts) stores the whole `{ vehicles, defaultVehicleId }` JSON in the existing `dbo.vehicle_profiles.data` column — no migration. Legacy single-profile rows are read as a one-vehicle garage with id = the user's id and overwritten in the new shape on the next save; `/api/vehicle-profile` was removed. PUT: CSRF before session, 16 KiB cap (413), ids `^[A-Za-z0-9-]{1,64}$`, unique, default must exist.

Frontend: pure helpers in src/domain/vehicle/garage.ts (ids passed in; `newVehicleId()` lives in useVehicleSettings.ts), browser copy in localStorage `trip-planner:vehicleGarage` migrated once from `trip-planner:vehicleSettings`, sync in useVehicleProfileSync.ts, garage dialog in VehicleSettingsModal.tsx, trip "Vehicle" select in the AuthenticatedApp hero card. The settings context keeps `mpg`/`profile` views of the default vehicle for compatibility.

Accepted risks: API rollback reads converted rows as "no profile"; whole-garage saves are last-write-wins.
