Pitfall: the QA visual gate and remote skill sources cannot be satisfied by subagents in this repo's harness.

In goal stop-form-restructure (2026-11-25) two things could not be done by agents. (1) Visual QA: there is no browser automation tool, and the app sits behind API-backed sign-in with no mock auth, so evidence-collector could only capture jsdom DOM; qa-evaluator correctly refused to PASS without screenshots and the user had to accept a manual checklist. (2) The web-design-guidelines skill only points at a remote URL; WebFetch from subagents was refused ("unable to verify domain"), while the orchestrator's own WebFetch worked. The implementer also skipped the design skills on the first pass and said so only in its report.

How to avoid it: at Phase 1, when the user picks `qa: run` for a UI goal, say that screenshots need a manual pass (or a mock-auth path) and agree the manual checklist then. When a goal depends on web-design-guidelines, the orchestrator fetches the guideline source itself before Phase 4, saves the relevant rules in the goal folder and lists that file in the implementer's and evaluator's Files to Read. Do not run the ui-ux-pro-max search script inside the repo without restoring the tracked __pycache__ files it rewrites under .agents/skills/.
