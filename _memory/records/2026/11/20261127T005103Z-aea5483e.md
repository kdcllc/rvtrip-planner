Goal timeline-map-link — outcome: shipped to PR #32 (branch feat/timeline-gantt-display, 2026-11-26), following goal timeline-gantt-display on the same branch.

Problem: clicking a timeline bar called scrollIntoView on the stop's card, scrolling the page down so the map (above the form in the single-column layout) left the screen.

What changed: a three-level interaction on the trip timeline. Hover/focus a bar highlights that stop's marker on the map (TripMap prop highlightStopId = previewStopId ?? currentStopId; attribute data-stop-highlight styled in App.css). Click selects: src/features/trip/carouselScroll.ts scrollCarouselToStop scrolls only the card strip sideways, TripForm reports the stop via onCurrentStopChange/onSelectStop, and TripMap pans (easeTo, zoom unchanged) only when the stop is outside the map bounds (focusRequest {stopId, nonce}). Double-click or the new "Details" button in the timeline header scrolls the page to the card. The auto-focus effect on load/re-date is sideways-only too.

Key decisions:
- No timeline-driven map popups: the map has one shared popup and hover refs, and removePopup calls onStopHover(null), which would clear the current stop. Marker highlight avoids that surface and the map cannot be unit-tested in jsdom.
- Scroll-settle guard in TripForm: the card strip uses scroll-snap and a 50 ms debounced "most centred card" listener; after a select, scroll-driven updates are suppressed until scrollend or 700 ms, and the pending debounce is cancelled on release, otherwise the selection flips to a neighbour.
- Double-click is only an accelerator; the Details button is the keyboard/touch equivalent.

Remember next time: this repo's eslint (react-hooks 7, set-state-in-effect) rejects a state setter inside an effect body; use refs for "re-run after rebuild" signals. Plan text that mandates code shapes should be lint-probed before Phase 3. Open follow-ups: 700 ms fallback where scrollend is unsupported; a focus request for a stop without a location is dropped.
