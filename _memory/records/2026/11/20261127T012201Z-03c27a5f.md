Pitfall: the trip's fuel estimate depends on finding a US state in the first stop's address text, and OpenStreetMap (Nominatim) addresses do not use the "City, ST 12345, USA" format. They spell the state out and put the ZIP in its own comma part, for example "Sugar Hollow Drive, Bristol, Virginia, 24202, United States".

Seen in goal fuel-start-state (2026-11-26): AuthenticatedApp took the second-to-last comma part and looked for two capital letters, found "24202", so no gas price was fetched and the summary showed "Estimated Fuel Cost: Data not available" for any trip whose first stop came from the OSM search. Trips with older "LA 71201, USA" addresses worked, which hid the bug.

How to avoid: parse addresses with src/domain/trip/stateCode.ts (extractUsStateCode / getTripStartState), which scans comma parts from the end and accepts both "VA 24202" and "Virginia". When adding any feature that reads location from address text, test it with both address formats. Remaining limit: a non-US address whose last part is a US state name (e.g. "Tbilisi, Georgia") resolves to that state.
