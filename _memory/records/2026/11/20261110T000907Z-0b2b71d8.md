Goal admin-test-email (2026-11-09, stacked on feat/branded-email). It adds an admin-only "Send test email" action.

API: `POST /api/manage/test-email` lives in `api/src/functions/adminTestEmail.ts`.
- Order of checks: csrfGuard, requireAdmin, then an in-memory per-admin 60 s cooldown (`Map`, keyed by lowercased email). The slot is reserved BEFORE sending, so concurrent requests can't both send, and released on failure or throw.
- It sends `sendTestEmail(admin.email, now)` (email.ts, branded `renderEmail`) to the signed-in admin only.
- Responses: 200 `{sentTo, sender}`; 429 `RATE_LIMITED` with Retry-After; 502 `EMAIL_FAILED` on ACS failure. 502 was chosen because the web apiClient maps 503 to "database waking" and auto-retries. A missing `ACS_CONNECTION_STRING` gives 502 (caught in send); a missing render-time setting gives 500 via fromException.
- Test seam: `__setNow(fn?)`, which also clears the map.

Contract: `TestEmailResponse` and `TEST_EMAIL_COOLDOWN_SECONDS = 60` are mirrored in `api/src/shared/types.ts` and `src/types/api.ts`.

Client: `adminClient.sendTestEmail()` returns `TestEmailResult`. apiClient cannot surface Retry-After for 429, so the client uses the constant.

UI: an "Email delivery" h3 section in AccessRequestsPanel with role=status/alert messages.

Tests: web suite 313, api suite 326. The new route was added to the security-regression admin and CSRF inventories.

Backlog: an isApiUser guard instead of the `as ApiUser` cast; route the panel success messages through the always-present sr-only announcer; aria-disabled instead of disabled.
